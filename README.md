# FunPay помощник (MVP)

Бот для заказов FunPay: приветствует покупателя после заказа, выдаёт написанный вами гайд, ставит услугу в очередь и отвечает на обычные вопросы с помощью локального Ollama. Отдельный `autoseller.py` ищет темы, готовит авторские гайды и публикует их через Golden Key после включения реального режима. Заказы и отправленные сообщения фиксируются в SQLite для защиты от повторной выдачи после перезапуска.

## Установка на Ubuntu VPS

Установите `python3-venv` и `python3-pip`, затем из каталога проекта запустите:

```bash
bash setup.sh
```

Скрипт создаёт `.venv`, устанавливает зависимости и запускает настройку: локально запрашивает Golden Key, модель Ollama и **отдельную цену каждого товара**. Ввод цены можно пропустить и указать её позже командой `.venv/bin/python bot.py price SKU СУММА`, например `.venv/bin/python bot.py price roblox_security_guide 2.50`. Цены хранятся в `prices.json`, а не в каталоге; повторная настройка сохраняет прежние значения. Указывайте фактическую цену по условиям площадки. Настройщик только сохраняет параметры; публикацию и поиск запускает `autoseller.py`.

Установите Ollama по инструкции [ollama.com/download](https://ollama.com/download), затем `ollama pull qwen3:4b`. В Qwen3 нет отдельного выпуска 3B; есть 1.7B и 4B. На маленьком VPS укажите в `.env` `OLLAMA_MODEL=qwen3:1.7b`. Модель отвечает только при доступном локальном Ollama; шаблонные ответы работают и без неё.

Укажите `FUNPAY_GOLDEN_KEY` в `.env` только на своём VPS. Это секрет с доступом к аккаунту продавца. Никогда не присылайте его в чат. Готовые гайды уже есть в `catalog.json`; новые темы добавляет `autoseller.py`. `match` — уникальная фраза из названия лота; для совпадения используйте длинные, разные фразы. Начальный каталог содержит четыре готовых авторских чеклиста на основе бесплатных официальных страниц Roblox, без заданных цен. Покупателю прямо говорится, что первоисточники бесплатны. В каталоге есть услуга прокачки Steal An Egg; `autoseller.py` её не размещает, пока нет работающего игрового исполнителя. Для замены гайда: `python bot.py guide roblox_security_guide path/to/your-guide.txt` (UTF-8). Не добавляйте чужие материалы без прав.

```bash
python bot.py catalog
python bot.py lot-drafts
python bot.py demo-order DEMO-1 "Гайд Roblox: защита аккаунта и завершение сеансов" BuyerName
python bot.py orders
python bot.py run
```

По умолчанию `DRY_RUN=1`: сообщения печатаются в консоль, но не отправляются. Когда проверите каталог и доступ, установите `DRY_RUN=0` и запустите `python bot.py run`. Запускайте **ровно один** экземпляр. На первый запуск реального режима лучше выбрать тестовый лот; первая загрузка событий может принести старые заказы — бот сохраняет обработанные ID, но не знает, были ли они обработаны другим софтом.

`python bot.py lot-drafts` выдаёт тексты лотов для четырёх готовых чеклистов с индивидуальной ценой из `prices.json` или пометкой «не задана». При запуске `autoseller.py` цены берутся из `prices.json`, а для незаданных ИИ сам выбирает цену без заданного диапазона. Скрипт публикует лот через Golden Key в разделе гайдов Roblox. Команда `price` сохраняет цену локально; для уже опубликованного лота она автоматически не меняется. Бот выдаёт только после события оплаченного заказа и совпадения названия. Он умеет отвечать на однозначную текстовую арифметику вида `капча: 7 + 9?` в чате заказа. Если сам FunPay выводит графическую CAPTCHA или проверку входа, бот останавливается для прохождения владельцем в браузере; он её не обходит.

Черновик услуги прокачки выключен (`enabled: false`): бот не выдаёт инструкцию и не обещает выполнение заказов по этой услуге. Список оплаченных заказов на работающие товары: `python bot.py orders`.

### Идеи лотов и новости

`python bot.py research "https://example.org/feed.xml"` берёт заголовки из открытой RSS/Atom-ленты и создаёт черновики идей в `ideas.json`. Адреса разрешены только `https`, локальные/приватные адреса отклоняются. Qwen составляет идеи без обещаний результата и без копирования статьи. `python bot.py ideas` показывает черновики; `python bot.py draft "Тема"` создаёт текст лота. Отдельный `autoseller.py` ежедневно просматривает официальный RSS объявлений Roblox, составляет новый авторский чеклист по достаточному фрагменту источника и пробует опубликовать не более одного нового гайда за цикл. Если источник слишком короткий, ИИ не отвечает или нет однозначного раздела, публикация пропускается.

### Автоматический поиск и публикация гайдов

```bash
.venv/bin/python autoseller.py once
.venv/bin/python autoseller.py loop
```

`once` выполняет один проход: загружает уже написанные гайды из каталога и ищет одну новую тему в официальном [RSS объявлений Roblox](https://devforum.roblox.com/c/updates/announcements/36.rss). `loop` повторяет это раз в сутки, пока процесс запущен. Для фонового запуска есть пример `funpay-autoseller.service`; сервис обработки заказов `funpay-assistant.service` работает отдельно. Нужны локальный Ollama и модель, указанная в `.env`. Цены из `prices.json` индивидуальны; для товаров без цены модель сама выбирает положительную цену.

Скрипт берёт доступные подкатегории из аккаунта FunPay и автоматически использует только однозначный раздел гайдов Roblox. Если подходящего раздела нет, он выводит доступные разделы и прекращает публикацию; после проверки раздела на сайте можно указать его ID в `.env` как `FUNPAY_GUIDE_NODE_ID=...`. Неверный раздел указывать нельзя. При `DRY_RUN=1` выводятся планы, лоты не сохраняются. При `DRY_RUN=0` лоты публикуются автоматически через неофициальную FunPayAPI. Файл `data/autoseller.json` хранит статус попыток и блокирует повтор после неопределённого результата запроса; такую попытку надо сверить с сайтом. Реальную публикацию без доступа к твоему аккаунту здесь проверить нельзя.

### Ограничения

Подключение к FunPay основано на **сторонней** FunPayAPI, а не на официальном API. Сайт может изменить формат событий. Этот проект не создаёт аккаунты Roblox, не запускает игровые скрипты и не передаёт игровые ценности; это требует отдельного исполнителя/интеграции и может нарушать правила игры. Для продажи заранее прокачанных аккаунтов не используйте демонстрационный каталог как обещание доставки: сначала нужно подготовить фактический товар и условия передачи. Правила FunPay предусматривают компенсации при блокировке аккаунта из-за запрещённых игровых ботов. Проверяйте правила обеих площадок перед публикацией. Нет гарантии заработка.

Данные заказов: `data/bot.sqlite3` (ID заказа, ник, тип товара, статус; без паролей и чатов). Удалить закрытые записи старше 30 дней: `python bot.py purge`. Для перезапуска как сервис используйте прилагаемый `funpay-assistant.service`, заменив `/opt/funpay-assistant` и `User=` под свою установку.

### Прокачка своих аккаунтов


Для собственных аккаунтов есть очередь. Пример: `python farm.py add-account my-01 steal_egg`, затем `python farm.py enqueue my-01 steal_egg 100`. `python farm.py jobs` показывает статус. Для своего внешнего исполнителя можно указать абсолютную команду в `farm_profiles.json` и запустить `python farm.py loop` как отдельный процесс; протокол — в `worker-protocol.md`. Результаты очереди не связаны автоматически с продажей аккаунтов; готовность товара должна подтверждаться фактической проверкой.

### Услуга прокачки Roblox

В `catalog.json` сохранён **отключённый черновик** услуги Steal An Egg. Покупатели не получают от бота ложное подтверждение такой услуги, а `autoseller.py` публикует только гайды. Обработчик `/level Ник Цель` сохраняет заявку без пароля и кодов, но пока не создаёт игровую задачу. Игрового исполнителя в архиве нет. Для Linux существует неофициальная среда Sober, но совместимость VPS и присланного Lua executor не установлена. Полный цикл входа, прокачки и выхода не реализован.

### Отдельный Lua для Steal An Egg

`python3 extras/steal_an_egg_source.py` скачивает [присланный владельцем SpeedHubX](https://github.com/LSSOPS/OpenSource/blob/main/SpeedHubX_Steal_An_Egg.lua) в `extras/downloaded/SpeedHubX_Steal_An_Egg.lua` и выводит SHA256. Подробности об игре и коде — в `script-research.md`. Внутри есть выключенные по умолчанию переключатели Auto Treadmill, Auto Steal, Auto Place Egg и Auto Hatch; файл дополнительно загружает два удалённых Lua-модуля. Исходник хранится отдельно: бот и `farm.py` его не запускают, он не предлагается на FunPay. Явную лицензию на перепубликацию в репозитории не обнаружил, поэтому исходник не вложен в архив. URL указывает на изменяемую ветку; скачать файл на VPS недостаточно для игры в Roblox — работающего клиента и исполнителя в проекте пока нет.

Вход по почтовому коду требует доступа к подтверждённой почте аккаунта и ввода на том же устройстве, где запрашивался код. После прокачки исполнитель должен выйти из Roblox; владелец может завершить другие сеансы через настройки безопасности. Эти шаги пока не выполняются `farm.py`: нужен реально работающий игровой исполнитель и безопасно настроенный вход на его устройстве. Не вставляйте коды или пароль в каталог, `.env` или сообщения покупателю.

### Возвраты за недоступную прокачку

Добавлен `leveling_guard.py`: возврат оплаты и снятие совпадающих лотов. Запуск и ограничения описаны в `REFUNDS.md`. Это не реализация игрового исполнителя.

### Гайды по оптимизации и другие категории

Каталог содержит шесть готовых гайдов, включая оптимизацию ПК и Roblox. Материалы написаны как короткие чеклисты на основе бесплатных источников; это прямо указано покупателю. У каждого товара своя цена в `prices.json`. Это желаемая цена продавца, фактические ограничения и комиссии определяет площадка.

Для каждого гайда в `catalog.json` теперь можно задать `category_keywords` (список слов для поиска подходящей категории с разделом гайдов) или `node_id` (точный ID раздела). Получить список всех доступных разделов: `.venv/bin/python autoseller.py sections`. Общий гайд ищет раздел гайдов в категориях ПК/Windows; если такого раздела нет, публикация пропускается с объяснением, другие гайды продолжают обрабатываться. Укажите подходящий `node_id`, если автоматический выбор неоднозначен. Поддержка выбора раздела работает для любой категории, но автоматическое создание новых материалов пока использует только RSS Roblox. Массовая публикация одного гайда во всех разделах не производится.

### Автозаполнение и авто-выдача

ИИ теперь заполняет лоты по найденным источникам для доступных игровых категорий FunPay. Для каждого подходящего раздела он создаёт отдельные темы без фиксированного количества «шесть», проверяет дубли и сохраняет курсор поиска. Публикация идёт с задержкой, чтобы не отправлять пачку запросов одновременно. Автоматического потолка числа созданных материалов нет; остаются ограничения FunPay, доступность источников, Ollama и однозначность раздела.

Гайд по каждой теме записывается в поле `secrets`, включается поле `auto_delivery=on`, а описание лота содержит только короткое описание выдачи. После покупки бот не дублирует материал в чате: его отправляет встроенная авто-выдача FunPay. Для проверки доступных разделов: `.venv/bin/python autoseller.py sections`. ИИ не создаёт лоты услуг прокачки, аккаунтов, читов или предметов.

### Обновление из GitHub

После клонирования публичного репозитория в `/opt/funpay-assistant` обновление выполняется одной командой:

```bash
cd /opt/funpay-assistant && bash update.sh
```

Скрипт скачивает изменения через `git pull --ff-only`, обновляет зависимости, проверяет синтаксис Python и перезапускает установленные systemd-сервисы. `.env`, `prices.json` и `data/` не хранятся в репозитории и не перезаписываются.
